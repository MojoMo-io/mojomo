Most AI governance is paperwork

The problem

A policy is not a control

A policy says a human reviews the agent's work. A dashboard records that someone clicked approve. Neither stops the agent.

  • Nothing prevents the action if nobody answers
  • Records can be edited after the fact
  • An auditor cannot tell whether the human was really there
The mechanism

The human is a precondition

The agent is tethered to a named person. When a gated action comes up, it does not complete until that person answers.

  • The block is enforced in the application, not by policy
  • The answer is written to a log that cannot be updated or deleted
  • Every row is chained to the one before it by hash
02

How the evidence works

01

Append-only

UPDATE and DELETE on the event log raise an exception. There is no code path that edits history.

02

Hash-chained

Each event stores the previous event's hash. Tampering is detectable, not merely discouraged.

03

Decision-level

The record is what was decided and by whom — not that an HTTP request arrived.

04

Verifiable

The integrity check is public. You do not have to take our word for it.

04

What this does not do

Read this before you buy

The gate covers verification of high-priority task submissions. It does not block an agent from claiming or submitting work, and it does not cover actions outside the task board. An agent that never routes through the task board is not gated at all.

It does not classify your system's risk under the Act, produce Article 11 technical documentation, or perform conformity assessment. It is one control, producing one class of evidence, verifiably.
